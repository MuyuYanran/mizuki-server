## 一、流程规则（Phase3-F 转正四项）

- **规则条文**：凡涉及 URL 拼装、绑定地址、cookie domain 的批次，提示词起草与评审
  两处均须列入检查单：hostname / cookie domain / 实际访问形态（localhost 与
  127.0.0.1 双形态、反向代理与公网域名）三者匹配一致性逐项核对；实现一律自
  `window.location.hostname` 或请求 Host 派生，禁硬编码 `127.0.0.1`。
- **缘起批次**：Phase3-C4（T4.1 实证 hostname 硬编码 127.0.0.1 在 localhost 与
  127.0.0.1 双访问形态下破坏 cookie host 匹配，C4 v2 修订为先例实现）。
- **先例链接**：REQUIREMENTS-PHASE3 §1.7 候选行（C4 先例 + C5 处置记录）；C4 SESSIONS。

### R2 前置检查条件化规则

- **规则条文**：批次提示词 §1 前置检查失败时，仅当以下**双条件同时满足**方可记偏差
  继续，任一不满足必须停止报告：①「可证实从未存在」而非「误删」（有撤销/未产出

### R5 恢复类 git 操作后审计

- **规则条文**：凡执行恢复/重建类 git 操作（bundle 或备份分支恢复、对象库事故恢复、
  `git filter-repo` 历史重写、force push、跨仓迁移）后，必须先做**双审计**再申报：
  ① 数账（测试基线数 + 文件数 + build/lint 实跑值）；② 文件清单 diff（预期差异逐条列出，
  非预期差异必须定因）。历史重写另须产出**提交哈希映射表（旧 → 新）**并落台账。
  禁以「`git status` 干净」或「本机跑得通」代替审计。
- **缘起批次**：Phase4-D4 侧车写入事故与 git 对象库事故（恢复载体 `1fb04b0`）；
  2026-10-20 发布前历史脱敏（方案 B，`filter-repo --replace-text`）——全部旧哈希失效，
  台账/ADR/SESSIONS 的引用必须逐条重映射。
- **先例链接**：`docs/SESSIONS.md`「发布 v1.0.0」节的「提交哈希重映射」清单；
  `docs/HANDOFF.md` 关键纪律第 8 条。

### R6 数账只认全绿轮

- **规则条文**：测试/构建/lint 数账**只认全绿轮**——含 worker 崩溃、环境性失败、超时中止的轮次
  禁作数账基线，须复跑至全绿或在台账显式标注「该轮不作数 + 原因」。分批跑的合计数必须同时给出
  **用例数与文件数**，并写明分批边界；申报值须能在本地或 CI 复现。
- **缘起批次**：Phase5-E1（484→488 轮出现 p9/p11 环境性失败，须复跑定真伪）；D4h 清账轮；
  U3-P3（本机全量单批 546/546 · 62 文件全绿后才申报）。
- **先例链接**：`docs/HANDOFF.md` 关键纪律第 2 条；`AGENTS.md` §3「验收三连 = test + build + lint 全绿」。

### R8 CI 可作远端数账依据（2026-10-21 新增）

- **规则条文**：CI 绿**可以**作为远端平台的数账依据，但须同时满足三条：① 该 workflow 覆盖
  install → 构建前置 → lint + test + build 全链；② 本地与远端**构建顺序一致**（含
  `@mizuki/shared` 预构建）；③ 申报时写明 **run 编号 + 提交哈希**。CI 红一律先定因再谈数账；
  **禁以「本机绿」覆盖远端红**——两平台差异必须查清是环境差异还是真实缺陷。
- **缘起批次**：2026-10-20 CI 修复（run 1–10 全红 → run 11 首绿）。两层缺陷均为
  「本机 Windows 绿掩盖远端 Linux 红」形态：第一层本地 `shared/dist` 已存在掩盖预构建缺失；
  第二层 `.cmd` 垫片穿透掩盖夹具对外部命令 `PATH` 的依赖。
- **先例链接**：`.github/workflows/ci.yml`；`docs/SESSIONS.md`「发布后补丁：CI 预构建修复」节
  （首绿 run 11 = `65a25cc`）。
