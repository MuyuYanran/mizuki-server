# ADR-006: 魔数嗅探自实现，不引入 file-type

| 字段 | 内容 |
|---|---|
| 状态 | 已采纳（人工已裁决） |
| 日期 | 2026-08-26 |
| 阶段 | P7（媒体与相册） |

## 背景

上传管线五件套第 2 步需要「魔数嗅探」识别上传文件真实类型（防伪造扩展名）。候选库 `file-type` 存在两个问题：`file-type@16`（最后一个 CJS 大版本）已停止维护；v17+ 为 ESM-only 包，与本项目 `module: commonjs`（NestJS + tsc CJS 产物）不兼容，强行接入需动态 import 或打包层特殊处理，复杂度不成比例。

## 决策

人工裁决：**不引入 `file-type`**。在 `apps/server/src/common/security/magic-sniff.ts` 自实现最小嗅探器（纯函数、零依赖），覆盖上传白名单的全部四格式：

- JPEG：`FF D8 FF`
- PNG：`89 50 4E 47`
- WebP：`RIFF`（0–3 字节）+ `WEBP`（8–11 字节）
- GIF：`GIF87a` / `GIF89a`

管线行为：嗅探结果必须与扩展名白名单映射一致（不符即拒）；sharp 重编码步骤对「魔数通过但内容损坏」的文件兜底拒绝（解码失败 → 400）。双保险下伪造件与损坏件均被拦截。

## 备选方案

- `file-type@16`：停止维护，安全更新不可得 → 否决。
- `file-type@17+`（ESM-only）：与 CJS 构建不兼容，接入成本与收益不匹配 → 否决。
- 仅靠 sharp 解码、不做魔数嗅探：无法区分「内容与扩展名不符」（如合法 JPEG 改名 `.png` 会通过解码），规格明确要求比对一致 → 否决。

## 后果

- 本阶段零新增依赖；嗅探面与白名单严格一致，后续新增格式 = 同时更新 `EXTENSION_FORMAT` 与嗅探分支（两处一处文件）；
- 若未来白名单扩展到四格式之外（如 AVIF），同步扩展 `magic-sniff.ts` 并补攻击用例。
