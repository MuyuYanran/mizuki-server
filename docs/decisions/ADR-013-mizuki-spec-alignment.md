# ADR-013: Mizuki 规格对齐基线原则

| 字段 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-28 |
| 阶段 | Phase2-B4（规格对齐审计） |

## 背景

一期 Server（P0a–P11）与二期前端（B1–B3）均按 `test/fixtures/mizuki` 假设开发；ADR-004（timeline 暂定映射）与 P4 偏差 4（字段核对以 fixture 为准）留下两处显式遗留义务。官方文档快照已落盘（`docs/refs/mizuki-docs/`，快照日期 2026-08-28），须建立「真实规格对齐」的长效基线，防止后续批次凭印象改规格或产生表单与存储不一致的幽灵字段。

## 决策

1. **快照唯一依据原则**：对齐审计以 `docs/refs/mizuki-docs/` 本地快照为唯一规格依据，禁止访问外网、禁止凭记忆/印象引用官方行为；审计总表每行必须附摘录引用（`摘录卡 §小节`，见 `docs/audits/b4-doc-excerpts.md`）或代码文件:行号。快照过期须重抓落盘并更新 README 清单后才可作为依据。
2. **审计处置四分类**：对齐差异只允许四种处置标记——【本批已修】（无风险对齐，当批落地）/【B2 落地（待裁决）】（涉服务行为/存量数据/新端点，与接线批次同批）/【维持现状】（必须给理由）/【需裁决】（呈报人工裁决，呈报者不实施）。禁止第五种「顺手改掉」。
3. **幽灵字段禁令**：凡 mapper 驱动的集合 schema（六类：diary/friends/projects/timeline/skills/devices），禁止在无服务与 UI 接线的批次单独新增持久化字段——新增字段会经 ADR-007 映射器自动长出表单控件，而未接线的消费方不认识该字段即静默丢弃，产生「表单能填、保存即丢」的幽灵字段。新增持久化字段一律与消费方接线同批落地（本批 SPEC-ALIGNMENT-B4.md T2-h4/h5 的 timeline/projects/skills 缺失字段即受此约束转 B2）。
4. **无风险对齐的判定口径**：仅当变更同时满足（a）纯校验强度（收紧/放宽/必填面）或纯测试资产与常量；（b）不改变控制器/服务行为逻辑；（c）不使既有合法存量数据失效（fixture 与测试数据可随批修复）——三条全满足才可当批落地。friends 必填面（desc/tags≥1）为规格显式点名的例外（存量 friends 数据下次编辑时按新必填面校验，属可接受的收紧成本）。

## 备选方案

- 无基线、逐差异临时裁量：同类差异各批处置不一，审计不可复现 → 否决。
- 全部差异冻结待一次性大对齐批次：对齐债务滚雪球，fixture 与官方样例持续脱节 → 否决（本批已证明可切出无风险子集先行）。

## 后果

- 后续涉及 Mizuki 数据规格的批次（B2 起）在动刀前先对 SPEC-ALIGNMENT-B4.md 相应行落处置，新增差异须补入总表并遵守本 ADR 四分类；
- 幽灵字段禁令使「schema 先行、接线后补」的开发路径显式违规——字段、服务、表单三者必须同批可见；
- 快照目录成为规格事实源，属于仓库资产纳入备份与评审范围（快照日期变更 = 须复核审计总表）。

## 追加（Phase2-B2，2026-08-28）：上传白名单终集、转码拆分与 tiff 两层关系

依九项裁决 2/3 落地后留档：

1. **上传白名单终集（裁决 3）**：`jpg/jpeg/png/gif/webp/avif` 六格式；`bmp`（sharp 0.35 预编译版无法解码，放行即必 400 死入口）、`svg`（XSS 面）、`tiff`（裁决排除）排除。tiff 魔数签名与单测保留。**【Phase3-C2a 修订见 ADR-017】**（bmp/tiff/tif 已准入，svg 维持排除）。
2. **转码拆分（裁决 2）**：相册上传管线移除「非 JPG 强转 JPG」，png/webp/gif/avif 原格式落盘；posts 封面（cover.jpg 硬约定）维持转码；媒体库直传维持现状（media 模块各自裁断，不再全局统一转码策略）。
3. **tiff 两层注记**：能力层（`magic-sniff.ts` 双端序魔数 `II*\0`/`MM\0*` 识别 + 单测）保留；放行层（上传白名单）排除。即：服务端能**认出** tiff 但不**收** tiff；用户手动放置到 Mizuki 目录的 tiff 文件不受影响，仍可经既有渲染通道正常展示——仅管理面上传不支持。
