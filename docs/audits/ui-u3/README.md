- 触发：用户要求「仿照 `http://127.0.0.1:6099/webui/`（NapCat WebUI）的菜单布局重构本项目布局，
  但保留本项目特色，不要变成纯抄袭，不要让本项目 UI 出现棱角或直线」。

## 1. 参考站拆解与「借鉴 / 不借鉴」清单

对 NapCat WebUI（React + Tailwind + NextUI）做了实测拆解（`bsk` 截图 + 可访问性树），
**只借布局骨架，不借配色、不借组件、不借内容**：

| 维度 | NapCat WebUI | 本批做法 |
|---|---|---|
| 侧栏 | 左侧固定竖列，**贴左边缘**，条目为「图标 + 文字 + 右侧短横杠」，选中项整行高亮 | 借鉴**竖列分组 + 条目式导航 + 底部动作区**；但侧栏改为**悬浮胶囊列**（离边缘有留白、无边框），选中项改渐变胶囊 + 圆点（不用短横杠） |
| 顶栏 | 通栏横条，左侧折叠钮 + 中间页面标题 | 借鉴**「顶部承载页面标题」**；改为**悬浮玻璃胶囊**（左右留白 + 圆角 + 发丝渐隐），右侧放 AI 助手 / 用户 |
| 底部动作 | 侧栏底部「切换主题 / 退出登录」两枚按钮 | 借鉴**动作下沉到侧栏底部**；保留 Mizuki 自己的**主题三态循环**（浅色 → 深色 → 跟随系统） |
| 内容区 | 圆角卡片矩阵 | 保留 Mizuki 自己的**仪表盘自由画布**（9 张卡片可拖可缩，布局本地持久化） |
| 配色 | NextUI 深色粉/紫 + 背景插画 | **完全保留 Mizuki 樱花粉调色板 + 明暗双主题 + 4 个预设换肤**，零改动 |

**「不要变成纯抄袭」的落点**：参考站的视觉特征（配色、圆角数值、字体、图标风格、卡片内容）一处未取；
借鉴面**只有三条信息架构**：竖列导航 / 顶栏标题 / 底部动作区。

## 3. 关键实现决策

### 3.1 标题上提：避免「双标题」

旧版每页都有页内大标题，改版后若保留，顶栏与页内会**上下两个标题**。处置：

- 顶栏标题取 `route.meta.title`（路由已有，**零改动**），集合页按 `route.params.type` 映射七类中文名
  （`/collections/diary` → 「日记」，不再显示「集合管理」）；
- 页内大标题**全部删除**，只保留副标题一行与操作按钮簇（操作簇改为右对齐）；
- 副标题集中在一张 `PAGE_SUBTITLES` 表里（11 条），编辑态走 `endsWith('/edit')` 判定；
- 死代码同步清理（4 个页面各删 1–3 条已成孤儿的 `.page-title` / `.page-subtitle` / `.card-header` 规则）。

**行为零改动**：路由表、meta、鉴权、manage 模式菜单收窄、登出语义逐字未动。

### 3.2 激活态判定修正（顺手修的真缺陷）

旧版 `el-menu :default-active="route.path"` 是**精确匹配**。改成自绘按钮后若照抄精确匹配，
`/settings` 会与 `/settings/ai` 抢激活态（后者进入时侧栏「设置」也高亮）。处置：

- `exact` 标记：只有 `/settings` 需要精确匹配（它是 `/settings/ai` 的前缀）；
- 其余条目按「路径本身或其子路径」命中；
- `el-menu` / `el-menu-item-group` 整体移除（不再依赖 EP 菜单组件的默认行为）。

### 3.3 「无直线」的实现手段：渐隐发丝线

`--mizuki-fade-hairline` 是**两端淡出**的 linear-gradient（12% 处才到实色，88% 后再淡出）。
用在：卡片头下缘 / 表头下缘 / 弹窗头尾 / 抽屉头 / 步骤条连接线 / 折叠面板头下缘 /
区块分隔 / AI 三键区上缘 / 侧栏分组分隔。

**踩坑记录（第一版失败）**：最初给 `.el-divider` 加 `border-top-color: transparent` + 背景层，
但 EP 的 `el-divider--horizontal` 是**整条 border-top 实线**，文字靠不透明底只盖住**中段**——
左对齐时右半段仍是实线。改用 `::before` 伪元素画渐变层后两端才真正淡出。

### 3.4 表格：格线全拆，改斑马底纹

`el-table` 的格线是 `border-bottom` / `border-right` 实线。处置：

- 单元格格线 `border: none !important`；
- 行区分靠**极淡斑马底纹**（`nth-child(even)`）+ 悬浮色；
- 表头下缘改发丝线（表头自带底色，遮住斑马纹穿到表头的接缝）；
- 卡内表格**再描一层边会成「双层硬边」** ⇒ `.el-card .el-table { border: none }`；
- 横向溢出条由灰实条改 6px 淡胶囊。

### 3.5 滚动条：外壳内隐去

浅色底上的滚动条轨道本身就是一条**硬直线**。处置：`.rail-nav` / `.stage-main` 的滚动条
`scrollbar-width: none` + `::-webkit-scrollbar { display: none }`。
**选择器需带 `:root` 前缀**提权（theme.css 的全局 `*:not(...)::-webkit-scrollbar` 特异度更高，
否则规则不生效——这是实测确认过的，不是猜测）。

## 5. 例外清单（明确「保留棱角 / 直线」的地方）

「不要出现棱角或直线」不适用于**内容语义本身需要直线**的场合，以下逐条登记：

1. **终端（LogTerminal）**：等宽字体的可读性优先，保留直角与等宽滚动条。
2. **编辑器内部排版**（Vditor / TipTap / CodeMirror 的正文区）：内容排版不属于面板外壳，
   其工具栏下缘已柔化，但正文内的表格格线、代码块边框保留。
3. **仪表盘自由画布的点阵网格**：圆点不是线；这是 Mizuki 自己的特色，保留。

## 6. 验收三连

| 项 | 结果 |
|---|---|
| `pnpm build` | **exit 0**（shared → server → web；`vue-tsc --noEmit` 0 错；1935 modules / 12.80s；CSS 493.32 kB / gzip 71.80 kB） |
| `pnpm lint` | **exit 0**（0 error / 0 warning） |
| `pnpm test` | **全绿：648 通过 + 4 跳过 / 74 文件 / 652 用例** |

**测试执行方式说明（据实）**：`pnpm test` 单批全量并行跑时出现 **3 个文件 4 个用例失败**，
失败全部是 **HTTP 429**（限流器被并行 worker 撞上）：

- `p9e-process-runs.e2e-spec.ts` ④ `DELETE` 后再取期望 200 得 429、⑥ 详情端点期望 200 得 429；
- 另 2 个文件同类。

处置与取证：

1. `p9e` **单独跑 8/8 全绿**（20.5s → 13.8s）；
2. 按 AGENTS.md §3 的规定（**分批 ≤6 文件 + `--maxWorkers=1`**）跑全量：
   **13 批全绿**，逐批计数 `37 / 70 / 63 / 45 / 42(+4 skip) / 56 / 40 / 57 / 64 / 56 / 57 / 37 / 24`；
   合计 **648 通过 + 4 跳过 = 652 用例 / 74 文件**（与 U4-AI2 批基线**逐字一致**）；
3. 本批 **零改动 `apps/server` 与 `packages/shared`**（`git status` 证实）⇒ 该 429 是
   **并行度问题**，不是本批引入的回归；与 AGENTS.md §3 已记录的「vitest 全并行在本机不可用」一致。

## 8. 已知缺口（登记，不追补）

1. **弹窗拖拽 / 拉宽未逐项手验**（机制未改，样式已改）。
2. **`el-menu` 组件被移除**：面板不再使用 Element Plus 菜单 ⇒ 失去 EP 菜单自带的
   「折叠态 hover tooltip」。本批用 `title` 属性替代（折叠态 hover 出原生 tooltip），
   视觉与 EP 原生 tooltip 不同。
3. **仪表盘画布的点阵背景**在浅色下仍偏明显（这是既有特色，未动）。
4. **表格横向溢出条**在窄屏下仍可见（已改淡胶囊 6px，非全隐）。
5. **`AiSettingsPage.vue` 的批量改动（550/183 行）不是本批产物**：那是 **U4-UI1** 批遗留的
   未提交工作（AI 设置页版式重做：区块化 + 生成参数改滑条）。本批在该文件内只有 **2 条分隔符柔化规则**
   （`--mizuki-fade-hairline` / `--mizuki-fade-hairline-v`），而这些分隔符元素**只存在于 U4-UI1 的新结构里**
   ⇒ **文本上无法拆分**（逐行还原 U4-UI1 前的结构会把 UI-U3 的柔化效果一并抹掉）。
   **提交时该文件整份入库**，并在提交信息中标明这条边界。
